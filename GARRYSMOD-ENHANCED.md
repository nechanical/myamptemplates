# Garry's Mod Enhanced AMP Template

A local/custom AMP Generic-module template derived from the current CubeCoders Garry's Mod template structure, with a more production-oriented GMod settings layout.

## What is improved

- Separate Quick Setup, Server, Gameplay, Workshop & Content, Sandbox Limits, Networking, Performance, Logging/SourceTV, Advanced, and Updates sections.
- Workshop collection install/mount controls plus `host_workshop_autoupdate`.
- Client Workshop downloads as **one Workshop file ID per line** instead of hand-generating Lua.
- Non-Workshop client resources as **one relative path per line** for `resource.AddFile`; prefix a path with `single:` for `resource.AddSingleFile`.
- AMP-managed `mount.cfg` and `mountdepots.txt`.
- Optional SteamCMD content packs for Counter-Strike: Source, Team Fortress 2, Half-Life 2: Deathmatch, and Day of Defeat: Source.
- Explicit networking/rate controls and conservative Source query/connection limits.
- Performance controls that avoid questionable "magic optimization" cvars.
- Two-tier custom cfg ownership:
  - `amp_user.cfg` runs before AMP-managed settings.
  - `amp_override.cfg` runs last and can intentionally override AMP.
- A deliberately minimal AMP-owned `server.cfg`, preventing an old unmanaged server.cfg from silently fighting the panel.

## Important paths

Inside the GMod install:

- `garrysmod/addons/` — local/non-Workshop addons.
- `garrysmod/gamemodes/` — local gamemodes.
- `garrysmod/cfg/amp_user.cfg` — normal custom settings generated by AMP.
- `garrysmod/cfg/amp_override.cfg` — final power-user overrides generated by AMP.
- `garrysmod/cfg/amp_workshop_ids.txt` — client Workshop file IDs generated by AMP.
- `garrysmod/cfg/amp_resource_files.txt` — local client resource paths generated by AMP.
- `garrysmod/lua/autorun/server/amp_resources.lua` — generated helper that processes the two lists.
- `garrysmod/cfg/mount.cfg` — managed directly from the AMP UI.
- `garrysmod/cfg/mountdepots.txt` — managed directly from the AMP UI.

## Installing from this repository

In AMP, go to:

`Configuration -> Instance Deployment -> Instance Management -> Configuration Repositories`

Add:

`nechanical/myamptemplates:main`

Fetch the repository and refresh the browser. Create a new **Garry's Mod Enhanced** instance and run Update once before starting.

## Local-only installation

AMP's Generic-module documentation also supports a local deployment-template folder. Under the ADS deployment templates directory, create a folder whose name starts with `LOCAL` and ends in `-main`, then place these files in it and refresh/fetch templates.

The documented path shape is:

`.../ADS01/Plugins/ADSModule/DeploymentTemplates/LOCAL-gmod-amp-enhanced-main`

The exact datastore prefix differs by operating system/install location, so use the ADS01 File Manager or your AMP datastore path rather than assuming a fixed absolute path.

## Workshop workflow

### Server-side Workshop install

Set **Workshop Collection ID**. GMod starts with:

`+host_workshop_collection <collection id>`

The collection installs/mounts Workshop items on the server.

### Client Workshop downloads

Put Workshop **file IDs**, one per line, in **Client Workshop Addon IDs**.

Example:

```text
104606562
150455514
```

Do not put a collection ID in this list. The generated helper calls `resource.AddWorkshop()` for each valid numeric line.

## Non-Workshop addons

Upload/copy server addons to:

`garrysmod/addons/`

For custom assets that clients also need, add virtual paths relative to `garrysmod/` under **Local Resource Files**, for example:

```text
materials/myaddon/icon.vmt
models/myaddon/prop.mdl
sound/myaddon/alert.wav
single:materials/myaddon/special.vtf
```

Use a FastDL URL for larger traditional content sets. Source ServerDL can be enabled, but the template defaults it off.

## Mounted content

The default `mount.cfg` already contains paths for the optional managed content packs:

```text
"cstrike" "../232330/cstrike"
"tf"      "../232250/tf"
"hl2mp"   "../232370/hl2mp"
"dod"     "../232290/dod"
```

Enable the corresponding content pack and run Update. You can add arbitrary additional paths in the **mount.cfg** textarea.

Single-player Valve content such as Episode One/Two is intentionally not automated here because those SteamCMD downloads can require an authenticated Steam account that owns the game.

## Migrating an existing GMod server

This template intentionally owns `garrysmod/cfg/server.cfg`. Before switching an existing instance:

1. Back up the old `server.cfg`.
2. Move ordinary custom lines into **Additional Server Settings**.
3. Move only deliberate last-word overrides into **Power User Server Settings**.
4. Upload local addons/gamemodes as normal.
5. Review `mount.cfg` and content-delivery settings.
6. Update, then start and inspect the AMP console/RCON output.

## Validation performed on this package

The generated package was checked for:
- valid JSON in every JSON manifest;
- unique `FieldName` entries;
- all update-condition settings existing in the config manifest;
- all meta-config mapped settings existing in the config manifest;
- all JSON files referenced by the KVP existing in the package.

This is a custom/local-use template. Test it on a spare instance before replacing a production server.
